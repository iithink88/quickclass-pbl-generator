适用：初中生（信息科技+数学+语文）｜ 设计：WorkBuddy（备课参谋）｜ 落地：QuickClass（探究操场）
🚩 驱动性问题：天气预报总说不准，体育课还常被雨淋——我们能不能自己做一个"班级气象站"，用自己的数据告诉大家今天能不能上体育课？

👥 三组分工（4 周完成）

数据获取组：研究怎么从免费天气 API 拿到温度、湿度、降水概率等数据。
数据处理组：解析 JSON，计算平均/趋势，判断"体育课建议"。
前端展示组：搭一个网页，把数据可视化，并做出"体育课建议"功能。

🧭 QuickClass 里怎么用（老师参考）

  • 课前摸底：在 QuickClass 设三问——「什么是天气 API？一句话解释」「你知道哪些免费天气数据源？」「做气象站你觉得最难的是哪一步？」AI 批改后，大屏一眼看清谁有编程底子、谁零基础，据此分组。
  • 课中苏格拉底引导：以"数据获取组卡在 API"为例，AI 不直接给答案，用类比带学生自己发现——

AI：你们想获取今天的温度，第一步要做什么？

学生：打开天气网站？

AI：对，但想让程序自动获取呢？你去银行取钱要带什么？

学生：银行卡？

AI：对。程序去"天气银行"取数据也需要一张"卡"，它叫什么？

学生：API Key？

AI：非常棒！去注册一个免费天气平台的 Key 吧。

  • 成果提交：学生在 QuickClass 提交网页链接 / 报告 / 演示视频，AI 按标准给初步反馈；老师一键汇总投大屏，全班共评。
  • 课后评价：上传作品到 WorkBuddy，按「问题清晰度 / 数据完整性 / 方案可行性 / 协作 / 展示」五维打分。
